# Nodejs_Broker unit tests

Run from `Nodejs_Broker`:

```bash
./run.test.bash          # node:26 container; installs dependencies if missing
# or, if Node 26 is installed locally:
npm install
npm test
```

The suite uses the built-in `node:test` runner with
`--experimental-test-module-mocks` (Node 26). Each test file registers its
module mocks **before** dynamically importing the module under test, so the
production sources stay untouched.

No certificates, Valkey cluster, HAProxy, MQTT client or Unix socket are
needed: every external dependency is mocked.

| module | mocked dependencies |
| --- | --- |
| `client_acl.mjs` | none (console only) |
| `client_collect.mjs` | none (console only) |
| `client_topics.mjs` | none (console only) |
| `config.mjs` | `fs`, `os` |
| `client_certificate_.mjs` | `./config.mjs`, `node:crypto` (`X509Certificate` only; hashing and signature verification stay real) |
| `client_session.mjs` | `./client_certificate_.mjs` (real `mqtt-packet` is used to inspect the generated bytes) |
| `redis_config.mjs` | `./config.mjs`, `fs`, `crypto`, `redis`, `setTimeout`, `process.exit` |
| `index.mjs` | `fs`, `net`, `./client_session.mjs`, `./redis_config.mjs`; signal handlers are captured from `process.listeners()` |

## Test layout

- `client_acl.test.mjs` – per-client ACL map, overwrite/remove/clear.
- `client_collect.test.mjs` – connected clients and pending challenges.
- `client_topics.test.mjs` – exact / `+` / `#` subscriptions, cleanup, and
  the current wildcard limitations.
- `config.test.mjs` – certificate reads, `tailscale0` IPv6 selection, and the
  Valkey / Redis configuration shape.
- `client_certificate.test.mjs` – chain rebuild, root pinning, expiry, leaf
  matching, and challenge-signature verification.
- `client_session.test.mjs` – CONNECT/AUTH handshake, ACL generation,
  SUBSCRIBE/PUBLISH handling, forwarding, PINGREQ/DISCONNECT and `delete()`.
- `redis_config.test.mjs` – node id derivation, endpoint advertisement,
  deduplication, TTLs and the periodic refresh timers.
- `index.test.mjs` – UDS server bootstrap, connection wiring, disconnect
  cleanup and signal handling.

## Known behaviour locked in by the tests

Some tests deliberately describe current (buggy) behaviour so a future fix is
a visible test change:

- `ClientTopic.getSubscriptions()` returns only exact-topic subscribers when
  an exact subscription exists, so wildcard subscribers miss the message.
- Overlapping wildcard patterns can deliver the same client twice.
- A shorter literal subscription is treated as a prefix match.
- `removeSubscription(topic, clientId)` deletes the whole topic.
- `ClientSession.delete()` throws before a successful AUTH because
  `internal.acl` does not exist yet.
- An empty verified-challenge `Set` is not rejected: `handleAuth()` checks
  `.length` instead of `.size`.
- `ClientSession` creates its parser without `protocolVersion: 5`, so a
  standalone AUTH packet is rejected by `mqtt-packet`; CONNECT still parses.
