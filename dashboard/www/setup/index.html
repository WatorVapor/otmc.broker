  -in client-space-leaf.csr \
  -CA client-space-inter.crt \
  -CAkey client-space-inter.key \
  -CAcreateserial \
  -sha384 \
  -days 36500 \
  -out client-space-leaf.crt \
  -extfile client-space-leaf.ext \
  -extensions v3_req
 注意 1：CSR 本身不携带证书扩展。签发时请使用脚本中的 client-space-leaf.ext （basicConstraints=CA:FALSE、keyUsage=digitalSignature、extendedKeyUsage=clientAuth）， 与 bash 脚本保持一致。 注意 2：从 IndexedDB 加载时会用私钥重新签名生成新的 CSR（ECDSA 签名具有随机性）， Subject 与公钥保持不变，新旧 CSR 均可被 CA 签发为等效证书。 适用场景：私钥仅需在当前浏览器内完成签名操作，且不需要将 .key 文件分发给其他 MQTT 客户端。 不适用场景：需要把私钥交给 mosquitto_pub、mqtt.js（Node）、ESP32 等外部 MQTT 客户端。 这类场景请勾选“允许导出私钥”，生成后立即把 .key 从浏览器中删除，或在服务器侧用 openssl 生成。 威胁模型：非导出密钥可防止私钥字节被 XSS 读取并外传；但恶意脚本仍可调用 crypto.subtle.sign() 对任意数据签名（“代理签名”）。 若你的应用需要抵抗此攻击，请使用 BFF 模式，由服务器持有私钥。
